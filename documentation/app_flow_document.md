# Book Barter App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user discovers the Book Barter app by visiting the landing page hosted at the main URL. The landing page showcases the platform’s purpose and invites the user to create an account or sign in. The user can choose to sign up with their email address and password or use Google OAuth to link their Google account. When the user selects the email sign-up path, they are taken to a form that prompts for name, email, password, and optional location details. After submitting, the system sends a confirmation email. Once the user clicks the verification link, they land on a welcome screen and are automatically signed in. If the user opts for the Google sign-up path, they are redirected to Google’s OAuth prompt. Upon approval, they return to the app on the welcome screen, with an account created and basic profile populated.

If a returning user selects the sign-in option, they provide their email and password or choose Google sign-in. Valid credentials lead them to the main dashboard. A “Forgot Password” link is available on the sign-in form. When clicked, it asks for the registered email, sends a reset link, and guides the user through password recovery. After resetting the password, the user can sign in normally. A persistent “Sign Out” button sits in the header of every authenticated page, logging the user out and redirecting them back to the landing page.

## Main Dashboard or Home Page
Once signed in, the user arrives on the main dashboard. A top header displays the Book Barter logo, a search input, and the user’s profile avatar. A vertical sidebar on the left lists navigation options labeled Library, Discover, Trades, Wishlist, and Account Settings. The main content area shows a personalized greeting with the user’s name and a summary of recent activity: new trade requests, nearby book recommendations, and pending wishlist matches. Each summary item has a “View All” link that takes the user to the detailed listing. The sidebar always stays visible so the user can switch sections at any time. The header search can be used from any page to jump directly to search results.

## Detailed Feature Flows and Page Transitions
### Library Management
From the dashboard, the user clicks Library in the sidebar and lands on their personal book collection page. Here the user sees a grid of book cards, each showing the book’s cover image, title, and trade availability. An “Add Book” button at the top opens a modal form. The form prompts for ISBN or manual entry of title, author, description, and trade visibility. The user must upload exactly four photos of the book. As they select images, upload indicators show progress. Once all photos finish uploading and the user submits the form, the page refreshes and the new book appears in the library grid.

If the user clicks on an existing book card, they view the book details page. This page displays the cover carousel, book metadata, current trade status, and action buttons to edit details or remove the book. Editing opens a similar form with pre-populated fields and allows photo replacements. Removing asks for confirmation, then deletes the entry and navigates back to the library grid.

### Search and Discovery
To discover books, the user selects Discover from the sidebar. The Discover page presents a search bar at the top and a filter panel for title, author, and distance radius. By default, results show books near the user’s saved location using geospatial queries. The user types keywords and clicks Search, or adjusts the distance slider and the list updates automatically. Each result appears as a book card. Clicking a card goes to its details page with an option to request a trade if the book is available.

### Initiating a Trade
On a book’s detail page, the user taps “Request Trade.” A modal appears asking them to confirm which book from their own library they want to offer. They choose from a dropdown of their available books and click Confirm. Behind the scenes, the app validates that both books are not already in active trades and then creates a trade record. Upon success, the modal closes and the user is automatically navigated to the new Trade chat page.

### Real-Time Chat
The Trade chat page displays both users’ selected books at the top, followed by a scrolling message window and an input field. Messages send instantly via the real-time provider and appear in the chat feed with timestamps. The user can send text, emojis, or pre-defined trade actions such as “Mark Shipped.” If either party goes offline, messages queue and deliver on reconnection.

### Completing a Trade
Once both users confirm they have received each other’s books, each clicks a “Confirm Receipt” button below the chat. When both confirmations are received, the trade status switches to Completed. The page then shows a prompt to leave a rating. When the user submits a rating and optional review, the system updates both users’ profiles and removes the trade from the active list.

### Ratings and Wishlist
After completing a trade or at any time via the sidebar, the user visits the Ratings page to see feedback they have received or given. Each entry shows star ratings and comments. The sidebar’s Wishlist link takes the user to their wishlist page. Here, the user adds books they want by searching book title or ISBN. If a new book matches someone else’s available book, the app notifies the user and shows it in the Discover section.

### Admin Panel
A special route group exists at `/admin` for users with admin roles. When an admin signs in, the sidebar includes an Analytics link. On the admin home, interactive charts display new user sign-ups, active trades, flagged listings, and system health metrics. Admins can click “Moderate Listings” to view any book flagged for review. Selecting a flagged book opens details with a decision panel to approve or remove content. Changes take effect immediately.

## Settings and Account Management
By clicking the profile avatar in the header and choosing Account Settings, the user enters their settings page. The page contains sections for Personal Information, Security, and Notifications. In Personal Information, the user edits name, email, password, and saved location. Changing the email triggers a confirmation step with a verification email. The Security section allows social connections management, letting the user link or unlink Google OAuth. There is also an option to enable two-factor authentication in the future. In Notifications, toggles control email alerts for trade requests, chat messages, and wishlist matches. After saving changes, the user remains on the settings page, and a toast message confirms the update. A “Back to Dashboard” link in the header returns them to the main dashboard.

## Error States and Alternate Paths
If the user enters invalid data in any form—such as a bad email format or missing required field—the system highlights the field and displays a clear error message explaining the issue. On sign-in or sign-up, too many failed attempts trigger a cooldown message or captcha challenge. If the user loses internet connectivity while browsing, a banner appears at the top indicating offline status. Pages switch to a cached offline mode or show a retry button. Attempting to access a restricted page without the right role, such as a non-admin accessing `/admin`, redirects the user to an Access Denied page that explains they do not have permission. In the rare case of server errors, a friendly error page invites the user to reload or contact support.

## Conclusion and Overall App Journey
A new user begins on the landing page, chooses a sign-up method, verifies their account, and lands on a personalized dashboard. From there, they add books to their library, explore nearby offerings, and easily start trades with other members. The real-time chat feature keeps the negotiation and shipping confirmations smooth. Completed trades lead to rating exchanges, and wishlists help the user discover matching offers. Account settings remain accessible at all times for profile updates and notification preferences. Administrators have a dedicated section for analytics and content moderation. Throughout the experience, clear navigation, instant feedback, and robust error handling ensure that every user journey—from signing up to completing a book swap—is seamless and intuitive.
